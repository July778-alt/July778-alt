# `MAIN STORY`

## AksesKita
**Public Complaint Reporting System**

<div align="center">

<img src="./assets/akses-kita-preview.png" width="90%" alt="Cuplikan tampilan proyek AksesKita"/>

<sub><em>// AksesKita — a public complaint platform, captured mid-build</em></sub>

</div>

**AksesKita** is one of my main school projects — a public complaint reporting platform built to make submitting and managing complaints more organized.

Users can submit reports, attach images, choose categories, set a location, and track progress. There's also a separate space for staff and admins to manage reports, users, categories, and the overall workflow.

**Tech Stack**
```text
Frontend    Next.js · TypeScript · React Native · Tailwind CSS
Backend     Express.js · TypeScript
Database    PostgreSQL
Other       Leaflet · OpenStreetMap · Git · GitHub · DBeaver
```

**What I Learned**
```text
→ Authentication              → File uploads
→ Role-based access control   → Maps & geolocation
→ API integration             → Pagination
→ Database design             → Admin dashboards
→ CRUD operations             → Project architecture · Git workflow
```

More than the syntax, AksesKita taught me that development rarely goes as planned. Most of the process looks like this:

```text
   build → break → find the problem → understand why
        ↑                                        ↓
        └──────── build again ← learn ←──────────┘
```

That loop is probably one of the most valuable things I've picked up so far.
